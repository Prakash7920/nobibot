# NOBI TRADE v0.1 — Local research terminal

White and dark themes, working replay engine and an experimental read-only Quotex practice feed adapter. This is a first runnable milestone, **not a finished broker auto-trading system**.

## Quick start — Tanglish

1. ZIP-ai extract pannunga. ZIP-kulla irundhu direct run panna vendaam.
2. Windows-la Python 3.12 or newer install irukkanum. Check: `py -3 --version`.
3. `START_NOBI.bat` double-click pannunga. Browser-la local app open aagum.
4. `Load sample replay` click pannunga. Idhu generated sample prices; live market illa.
5. `Next candle` use panni step-by-step paarunga, illa `Start engine` click pannunga. One second-ku one candle advance aagum.
6. Auto Trading page-la amount, expiry, limits set pannitu automatic **local paper** orders enable pannalaam. Save pannumbodhu engine pause-la irukkanum.
7. Live/Replay page-la signal arrows, Trade Journal-la results, Logs-la actions paarkalaam.
8. Window close panna app stop aagum. Restart-la automatic trading OFF. Open paper positions are voided and stakes refunded — these are never broker positions.

`python app.py` also works on Linux/macOS. Core app uses Python standard library only, without npm, CDN or API key. A working Python installation is required; this is source + launcher, not a standalone .exe.

## Experimental Quotex connection

1. Close the running app (Ctrl+C in its terminal).
2. Run `INSTALL_CONNECTOR.bat`. This installs the pinned unofficial PyQuotex dependency in `.venv` and needs internet.
3. Run `CONNECT_QUOTEX.bat`.
4. Enter your email/password only in the local terminal. Never send them in chat. Password input is hidden. If authentication requires an OTP or browser challenge the upstream library may require terminal interaction or fail; there is no bypass.
5. The adapter explicitly selects PRACTICE and verifies both client and API account modes. It reads assets, history and fresh ticks; it does not call broker buy/sell functions.
6. Select the exact market. USD/INR normal and USD/INR OTC are different assets. There is no silent substitution. Unavailable assets are not fabricated.
7. Compare symbols, timeframe, UTC times and latest prices with your broker. Keep the system clock synchronized. Feed latency, candle boundaries and payout mapping need local verification.
8. Start engine once fresh data is visible. Only closed candles are analyzed; stale feeds pause signals. Signals are generated by NOBI rules, not official broker recommendations.

The adapter is based on inspected source revision `a50a030b425937fec4595b1ff1c226e160c52943` of https://github.com/cleitonleonel/pyquotex. It is unofficial, not endorsed by Quotex, and compatibility can change. Authentication and broker prices have **not** been tested with a real account here. A menu alone is not proof of connection.

The third-party package can cache session cookies/tokens locally. Treat its session files like passwords. Do not share your entire installed folder after connecting. NOBI logs do not contain raw broker errors or credentials. No claim of encrypted upstream session storage is made.

## CSV schema

`time,open,high,low,close,volume`

- Unix timestamp in **seconds**, candle-open time, ascending, unique.
- Continuous 60, 120, 300 or 900-second intervals. Missing intervals are rejected.
- At least 40 rows, maximum 20,000. Volume optional.
- Import does not establish that prices match any broker. Keep source provenance separately.
- The first 40 candles warm up the rules. Entries use the following candle's open to avoid future leakage. Expiry is a whole multiple of the candle interval. Settlement uses the corresponding future candle open.
- The last row is a settlement/entry boundary, not a closed-candle signal observation.
- End-of-data open trades are voided/refunded. Backtest drawdown is realized, not intratrade mark-to-market.
- Payout is fixed by user assumption; latency, missed fills, fees, changing payout and broker-specific expiry behavior are not simulated.
- Results on synthetic samples only test software. Historical results are not held-out validation unless you independently chose held-out data.

## Strategy rules

All enabled rules must agree on CALL or PUT; otherwise WAIT. At least 35 closed candles required.

- Trend: EMA9 above EMA21 and close above EMA9 → CALL; inverse → PUT.
- Momentum: RSI calculated from the most recent 14 close-to-close changes (simple average, not Wilder smoothing). 52–75 → CALL; 25–48 → PUT; otherwise WAIT.
- Breakout: close beyond previous 10 candle highs/lows.
- Volatility filter: reject flat ranges and a candle more than three times the mean range of the last 14 candles.

These rules have no claimed predictive edge or calibrated confidence. Strategy AI is the requested section name; no external AI model is included.

## Risk behavior

One open paper trade at a time. Available balance and projected worst-case new loss are checked before entry. Limits apply per replay session and UTC replay day, **not** across all historical runs. Journal stats combine all runs. Replay reload starts a new session; it is not a way to evaluate a continuous month of risk limits. No Martingale.

Pause/emergency stops new execution and pauses replay time. Existing positions settle when Next candle / Resume advances to expiry. Restart voids open paper trades with a refund. Do not confuse this behavior with broker account settlement.

## Telegram

Run `START_WITH_TELEGRAM.bat`, enter token/chat ID locally, then use the Telegram page to send a test. Create/configure your bot separately and ensure it can message the chosen chat. The launcher prompts visibly for the token: do not screen-share it. Tokens live in process environment, not the NOBI SQLite database. Alerts go only to the configured destination. Replay messages explicitly say SAMPLE/CSV. A successful configuration check does not prove delivery; check Logs.

To use Telegram with the broker feed, set the same `NOBI_TELEGRAM_TOKEN` and `NOBI_TELEGRAM_CHAT_ID` environment variables locally before launching `CONNECT_QUOTEX.bat`.

## Local security / diagnostics

The server binds to 127.0.0.1 only, rejects unexpected Host/Origin, requires a per-process request token for mutations, uses no third-party browser scripts, and escapes user/broker strings in tables. Do not expose this development server to the internet. Local processes can access it. SQLite state is in `data/nobi.sqlite3` and is not encrypted. Back up this file only while the app is stopped; do not include third-party session caches.

Port busy: close another NOBI terminal or run `py -3 app.py --port 8766`. Python missing: install a supported Python 3 version and ensure the Windows launcher `py` exists. Do not use Python 2.7.

## Tests

From this folder: `python -m unittest discover -s tests -v`.

The included unit suite verifies accounting, draw refunds, duplicate signals, loss limits, emergency stop, broker-order lock, nonfinite input, immutable signal records, configuration locks, restart refunds, CSV validation, candle validation, deterministic backtests and next-open entry. Browser smoke-test results are recorded in VALIDATION.md.
